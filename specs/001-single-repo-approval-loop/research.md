## R2. Windows 权限隔离边界（P0-01，阻断项）

### 2.1 边界分层模型（OS 级为准，工具级为纵深）

```text
┌─ 操作系统级隔离（权威边界，缺失即不安全）────────────────┐
│  ① 安全主体分离：Agent 以独立受限主体运行（见 2.2）        │
│  ② DACL 显式拒绝：对未授权客体 Deny Read / Deny Write     │
│  ③ 进程边界：Job Object 纳管（终止进程树；禁用 breakaway） │
│     + 受限令牌/低完整性（仅补充写入限制）                  │
│  ④ 网络边界：按可执行文件的出站白名单                      │
│  ⑤ 凭据边界：API Key 仅注入 Agent 进程环境变量；           │
│     不入 DB、不入快照、不入日志                            │
├─ 工具级约束（纵深防御，不得单独依赖）──────────────────┤
│  ⑥ disallowed_tools（写文件/执行命令/网络类）+ 读路径白名单│
│  ⑦ PreToolUse Hook deny（仅作附加层）                      │
│  ⑧ AgentAdapter 载荷校验（manifest 白名单）                │
└──────────────────────────────────────────────────────────┘
```

**关键修正（P0-A）**：

- **MIC（强制完整性控制）默认只限制「写入」高完整性客体（No-Write-Up），
  不限制「读取」**——低完整性级别本身不构成读取隔离。
- **受限令牌与 MIC 是两种不同机制，不得混同**：受限令牌可通过
  restricting SIDs / deny-only SIDs 使访问检查二次失败，从而**有能力
  限制读取**；但其生效性取决于客体 DACL 的授权 SID 是否被排除在
  受限 SID 集/启用 SID 之外，须逐客体实测（S14 探针）。
  读取隔离的权威手段仍为 **DACL 显式 `Deny Read`**（可与受限令牌
  SID 集组合强化；或独立低权限用户/沙箱），不得把"不向 Agent 传原
  仓库路径"当作访问隔离。
- **路径不传 ≠ 访问隔离**：路径保密仅最小化暴露面，可被目录枚举、
  符号链接或可猜测路径穿透；路径不传与 DACL Deny 必须同时具备。
- Hook 与提示词是**附加缓解**，不是安全保证（工具层可被实现缺陷穿透）。
- 下列机制**全部为候选配置，未证明有效**；生效性由 FV-3/实现期实测与
  运行时权限探针（2.2）验证，验证完成前不得表述为"已达成隔离"。

### 2.2 安全主体与访问控制矩阵（P0-A）

| 主体 | 身份载体（候选） | 对审批 DB | 对原仓库 | 对全量归档 | 对物化授权子集 | 对用户目录 | 对凭据 |
|---|---|---|---|---|---|---|---|
| FastAPI 后端 | 服务账户（Medium 完整性） | 读写（唯一） | 只读（git 读对象库） | 读写（证据保管） | 读写（物化发放） | 不访问 | 读取并注入 |
| Agent 工作进程 | 独立受限主体/受限令牌（低完整性） | **Deny**（DACL） | **Deny Read/Write**（DACL，非"不传路径"） | **Deny**（不挂载） | **Read**（DACL 授予） | **Deny Read/Write** | 仅 env 注入 |
| Agent 子进程（git/工具） | 继承 Agent 主体 | Deny | Deny | Deny | Read | Deny | 继承 env |
| 浏览器 | 用户会话凭据 + CSRF 令牌（R7/P0-B） | 仅经后端 API | 无 | 无 | 无 | — | 不可见 |
| 用户本人 | OS 用户 | 经 UI | 自由 | 自由 | 自由 | 自由 | 自行保管 |

**本地文件读取拒绝（P0-A）**：Agent 主体对原仓库根、用户 Profile、
审批 DB 文件、凭据存储、全量归档的 DACL 显式 `Deny Read`（读与写
分别设置，读取拒绝不可省略）；物化授权子集目录仅授予 Agent 主体
`Read`（最小授权，见 R3.5）。

**Job Object 定位（P0-A）**：提供生命周期纳管（kill-on-close 终止
进程树、资源限额，支撑 FR-034 取消语义），**不是独立安全边界**——
须与受限令牌/DACL 组合；**禁用 breakaway**（不设置
BREAKAWAY_OK/SILENT_BREAKAWAY_OK）；子进程逃逸须专项测试（S15）。

**运行时权限探针（fail-closed，S14）**：启动自检以合成探针文件实测
——Agent 主体对"应拒绝客体"（原仓库样本、DB、用户目录）读取必须
失败、对"应允许客体"（物化子集）读取必须成功；任一不符拒绝进入生成。

**Windows 机制候选清单（ADR 待批，均未证明有效，FV 验证）**：

| 层 | 候选机制 | 说明 / 风险 |
|---|---|---|
| 读取隔离 | DACL：未授权客体对 Agent 主体 Deny Read（原仓库/DB/用户目录/归档） | 主防线；可与受限令牌 restricting SIDs 组合强化；符号链接逃逸需额外校验（R3） |
| 进程令牌 | 受限令牌（restricting SIDs / deny-only SIDs） | **可参与限制读取**（二次访问检查），但须与 DACL 组合并逐客体验证（S14）；单独不作主防线 |
| 完整性级别 | MIC 低完整性 | **默认仅限写**（No-Write-Up），不限读；只作补充写入限制 |
| 进程容器 | Job Object（禁 breakaway + kill-on-close） | 生命周期/取消语义；安全能力有限 |
| 强隔离备选 | 独立低权限 Windows 用户 / AppContainer / Windows Sandbox | 效果最强、运维复杂；DACL 方案经 FV 证明不足时升级 |
| 网络 | Windows 防火墙按可执行文件出站白名单（仅授权 AI 端点） | 与 R5 L4 配合；FV-7 验证 |
| 凭据 | 环境变量注入 Agent 进程（受限环境块） | FR-042 |

### 2.3 自动加载内容的处理（设置/Hooks/MCP/插件/不可信规则）

**风险**：Agent 引擎（Claude Code 系）可能从工作目录自动加载项目级
settings、Hooks、MCP 服务器配置、插件与规则文件（如 `.claude/`、
`.mcp.json`、`CLAUDE.md` 类文件）。目标仓库中此类内容**全部是不可信数据**
（FR-014），自动加载即等于提示注入获得执行面（FR-043）。

**强制策略**（写入 AgentAdapter 契约）：

1. Agent 进程工作目录 = ADLL 自建的**净化运行目录**（仅含宿主组装的
   prompt 与 manifest 放行文件）；目标仓库快照以数据路径显式传参读取，
   不作为配置根。
2. 配置目录指向 ADLL 管理的干净目录（环境变量隔离，具体变量名 FV-1
   核实）；**项目级 settings/hooks/MCP/插件一律不加载**。
3. Hooks 白名单 = 仅 ADLL 自带的 deny 类 Hook；MCP 服务器 = 空集合；
   插件 = 不加载。变更须配置审计 + 人工批准。
4. 快照中捕获的任何规则/提示词文件仅进入分析数据管道（模型上下文按
   「数据」标注传入），绝不进入系统指令层。
5. 验收：S2/S10（quickstart）构造含恶意 `.claude/`、`.mcp.json`、
   规则文件的合成仓库，断言其不被加载、不产生任何工具调用。

## R3. 只读分析、Git 快照与完整性证据（P0-04，阻断项）

### 3.1 快照生成机制对比（git archive vs worktree，真实差异）

| 维度 | `git archive <sha>`（**候选首选**） | `git worktree add <dir> <sha>` |
|---|---|---|
| 对原仓库 `.git` 元数据 | **只读**（读对象库，不写管理文件） | **有写入**：在 `$GIT_DIR/worktrees/<name>` 登记管理元数据（共享对象库与引用；`remove/prune` 前残留） |
| 对原仓库工作区 | 无影响 | 无影响（检出写入新目录） |
| 与 FR-006/脏工作区关系 | 天然安全 | 违反"不触碰用户仓库"精神；worktree 操作可与用户 git 操作产生引用锁竞态 |
| LFS | 导出**指针文件**（不跑 smudge） | 检出时可能触发 LFS smudge（读网络/本地 LFS 存储，行为依赖环境） |
| submodule | **不包含**子模块内容（只含 .gitmodules 数据） | 不自动递归子模块 |
| 符号链接 | tar 中保留为链接条目 | 检出为链接 |
| 结论 | **默认采用** | 仅当用户单独授权"允许写入 .git/worktrees 元数据"时作为备选；否则禁用 |

**候选补充方案**：`git clone`（file:// 本地克隆到隔离目录）——对原仓库
只读，适合需要完整工作树语义的场景；代价是磁盘与耗时。三者取舍进
ADR-C3 附录；默认实现 git archive。

### 3.2 快照生命周期（生成 → 保留 → 校验 → 恢复）

1. **生成**：`git archive <full_sha>` → 解包到隔离快照目录；
   记录 origin 元数据（命令、完整 SHA、对象格式、时间戳、归档 SHA-256）。
2. **保留**：快照至少保留到引用它的全部执行达终态且核验完成
   （默认再保留 30 天，可配置）；内容寻址归档（tar 的 SHA-256）
   作为证据副本。
3. **校验**：生成前对分析范围文件清单 + SHA-256 基线；生成后重算比对；
   归档哈希独立复核（FR-013/045）。
4. **恢复/追溯**：即使原 Commit 后续丢失，保留的归档仍可复盘历史
   方案与审批证据；但按 FR-048，**新生成与新审批仍被阻止**（不回退
   HEAD），基准状态 = unavailable。

### 3.3 特殊内容处理策略

| 内容 | 策略 |
|---|---|
| Git LFS | archive 导出的是**指针文件**：方案中显式标注「LFS 内容未包含」；如任务需 LFS 实体，须在授权范围中显式列入并重新确认（属范围扩大，FR-015） |
| submodule | V1.1 单仓库范围：不递归拉取；`.gitmodules` 作为数据标注「子模块内容未包含」；需要时按新仓库关联处理（超 V1.1 范围） |
| 符号链接 | 归档解包时**不跟随**；记录链接目标路径；目标逃出快照根的一律视为可疑（S 系列断言），链接不作为读取通道 |
| Commit 丢失 | `git cat-file -e <sha>^{commit}` 预检失败 → 基准 unavailable，阻止生成与新审批（FR-048）；历史证据用保留归档复盘 |
| 稀疏/巨型仓库 | archive 范围限定 manifest 允许路径（减少出站面，见 R5） |

### 3.4 完整性证据构成（FR-045"证据充分性"的操作定义）

恢复补充核验判定"证据充分"必须同时具备：①可信生成前基线（清单+哈希，
含创建时间与来源命令）②原分析快照引用（内容寻址归档）③生成执行记录
（工具调用日志、状态转移审计）④权限隔离证据（生效的 OS ACL/令牌/
防火墙与拒绝规则配置快照）。四缺一或无法确认原生成完整完成 → 保持
「未确认」或核验失败（Q2 裁定不变）。哈希一致**不得**单独放行。

### 3.5 全量归档与物化授权子集（P0-C）

- **可信后端**：可保存**完整快照归档**作为证据（SnapshotArchive，
  内容寻址全量副本）；仅后端主体可读写（访问矩阵见 2.2）。
- **Agent 进程**：只接触**物化授权子集**——后端按 send_manifest 将
  已授权文件物化到独立只读目录（MaterializedSubset），其 DACL 仅授予
  Agent 主体 Read；**未经授权的仓库文件对 Agent 进程不可读**
 （DACL Deny Read，而非仅"不列入清单"）。
- 全量归档**永不直接挂载**给 Agent 进程；物化子集每次生成独立生成、
  用毕销毁；物化清单（路径+哈希）留存为审计证据。

## R4. 状态与历史一致性（P0-03，阻断项）

### 4.1 双层数据模型（不可变历史 vs 可变当前）

```text
历史事件层（append-only，禁止 UPDATE/DELETE）
  RequirementVersion / ProposalVersion / ApprovalEvent /
  GenerationExecution 终态记录 / VerificationAttempt /
  LateResultRecord / SendAuditRecord / SecurityEvent / AuditLog
当前状态层（可变投影，事务内更新）
  Task.current_* 指针 / Baseline.availability / 授权状态 /
  执行"当前状态"投影（终态后冻结）
```

- 任何"当前状态"都可由历史事件重算（投影可重建），作为一致性校验。
- 审计机制：AuditLog 记录 actor（user/agent/system）、动作、前后状态摘要、
  时间戳；可选哈希链（prev_hash 候选，防篡改增强，ADR 定）。

### 4.2 竞态与重复请求的确定行为

| 场景 | 机制 | 结果 |
|---|---|---|
| 取消后迟到结果 | 执行进入终态（cancelled）后**不再改写**；迟到结果写独立 LateResultRecord | 不创建方案版本、不改核验状态、不隐式批准（FR-035）；原终态与原因保留 |
| 恢复后补充核验 | VerificationAttempt **每次尝试一行**（append-only）；当前核验状态 = 最新有效尝试的投影 | 历史尝试全保留；「未确认」不被覆盖，只能被新尝试替代且新尝试须证据充分（FR-045） |
| 并发批准 | SQLite **部分唯一索引** `UNIQUE(proposal_version_id) WHERE decision='approved'` + 事务 `BEGIN IMMEDIATE` | 唯一生效一条；落败方收到 409 + 拒绝审计（FR-031，SC-005） |
| 并发生成 | 部分唯一索引 `UNIQUE(task_id) WHERE status='running'`（活跃执行唯一） | 后到者幂等返回既有执行 ID |
| 重复请求（网络重试/双击） | `Idempotency-Key` 头 + 请求摘要存储 | 同键同摘要 → 重放原响应；同键异摘要 → 409 |
| 需求正式保存并发 | 版本序号分配在 `BEGIN IMMEDIATE` 事务内（max(seq)+1） | 序号唯一连续，无覆盖 |
| 状态转移 | 事务内 compare-and-swap（`UPDATE ... WHERE status=expected`）+ 域状态机校验 | 非法转移拒绝并审计（FR-027） |

### 4.3 批准目标版本规则（P0-D；采纳推荐规则）

- 任务"当前方案版本" = 该任务 `seq` 最大的 ProposalVersion；
  UI 默认展示当前版本。
- **仅允许批准「当前有效方案版本」**：服务端在同一事务内复核三项
  前置**全部**成立——①目标版本 = 当前方案版本（max seq）；
  ②目标版本的 requirement_version_id 与 baseline_id 分别匹配任务
  **当前需求版本**与**当前分析基准**；③目标版本关联的最新
  VerificationAttempt.status = verified。任一不成立即拒绝。
- 批准请求仍携带显式版本号（防误操作/可审计），服务端以该版本号
  与当前版本一致性校验为准，不隐式替换目标；与 FR-028 五要素绑定
  一致（五要素即本次事务中复核通过的同一组值）。
- **过期版本操作**（版本号 ≠ 当前版本，或需求/基准已变更）：返回
  **409 approval_target_stale** 明确冲突 + 提示重新审阅当前版本；
  **不得写入任何 approved 事件**，不得产生"已批准但立即无效"的
  误导性记录（历史意图以审计日志记录）。
- **事务一致性（P0-D）**：前置复核 + ApprovalEvent 插入 + 任务投影
  更新在同一 `BEGIN IMMEDIATE` 事务完成；并发场景由
  `ux_approval_once` 唯一索引与 CAS 收敛（4.2 表）。
- 驳回→再批准（同版本仍为当前且核验通过）：允许产生新的 approved
  事件（唯一索引仅约束 approved 单条）；驳回事件保留。

### 4.4 SQLite 事务与隔离（候选实现要点）

- WAL 模式；单写者连接池（后端进程内串行写队列候选）。
- 状态转移与事件写入**同一事务**；事件写入成功才更新投影。
- 崩溃恢复：事务原子性保证半成品不可见；中断执行按 FR-037 呈现。

## R5. 出站数据与授权强制（P0-02，阻断项）

### 5.1 四层强制漏斗（P0-C 修订：三个安全面分别定义、分别强制）

```text
L1 宿主授权清单（唯一权威）：OutboundAuthorization 生成 send_manifest
    （任务+基准+接收方+范围+有效状态五条件校验，FR-015）
L2 文件读取权限面（OS DACL，见 R3.5）：Agent 仅可读物化授权子集；
    未经授权的仓库文件对 Agent 不可读——此面管"能不能读到"
L3 实际模型请求内容面（宿主组装 + 记账）：prompt + 需求文本 + 反馈 +
    manifest 放行文件 + 工具返回内容 = 实际入模内容；Agent 不得自行
    追加——此面管"实际发出了什么内容"（SendAuditRecord 全量记账）
L4 网络发送目的地面（OS 级兜底）：进程出站白名单（仅授权 AI 端点）；
    未授权目的地址阻断并产生安全事件——此面管"发往何处"
```

三面必须**分别**强制与验证：L2 限读、L3 记账并裁剪入模内容、L4 限
目的地；任一面独立失败均阻断。L2 通过 ≠ L3 合规（读到的未必都入模），
L3 合规 ≠ L4 合规（内容合法仍可能发错地址）。

### 5.2 覆盖范围（P0-02 明确要求）

- **需求文本、修改意见**：发送前计入发送内容清单（manifest 附录），
  属已授权数据类型之一，须在授权确认时展示。
- **源码**：仅 manifest 放行路径（默认排除敏感/密钥/环境配置/高风险）。
- **工具返回内容**：工具读到什么就等于外发什么（模型上下文 = 外发面）；
  生成 SendAuditRecord 时按实际入模内容记账，而不仅按文件清单。
- **系统指令**：ADLL 自有系统提示不属于授权外发对象，但其中不得
  拼接未授权内容。

### 5.3 越权外发阻断与审计验证

- 阻断路径：L1 复用五条件不满足 → 重新授权流程；**L2** 越界读（文件
  读取权限面）→ DACL/工具拒绝 + 安全事件；L4 未授权端点 → OS 阻断 +
  安全事件。任一层失败即**阻断生成**
  并明确告知受阻原因（FR-015）。
- 审计验证（验收 S9/S11）：SendAuditRecord 保留 `payload_manifest`
  （路径/哈希/数据类型）、`authorization_id`、请求侧内容摘要；
  抽样比对"审计记录 ⊇ 实际入模内容"，出现未记账内容 = 阻断级缺陷。
- **FV-7 观测边界（P0-C，不夸大）**：仅使用**合成数据**（合成 canary
  文件与工具返回）验证实际入模内容一致性。可靠观测面 = 宿主组装点
  记账 + 工具调用日志 + 网络目的地址（防火墙/代理日志）。
  **无法可靠观测的部分**（如进程内已加密传输的请求体逐字节内容、
  提供方侧实际留存）**明确记录为「未验证」**，验收报告不得声称
  全量通过；未验证项进入遗留风险清单。
- **不预设 SDK/CLI 满足全部要求**：L2 依赖 DACL 实现与探针、
  L3/L4 依赖 FV-3/FV-7 实测；不达标 → 见 R1 降级路径。

### P1-01 Git 对象 ID 长度（SHA-1 / SHA-256）

- **已核实工程事实**：Git 默认对象格式 SHA-1（40 hex）；`git init
  --object-format=sha256` 产生 SHA-256 仓库（64 hex），git 2.29+ 支持。
- **适配策略**：关联仓库时执行 `git rev-parse --show-object-format`
  记录 `object_format ∈ {sha1, sha256}`；schema 中 commit SHA 字段校验
  `^(?:[0-9a-f]{40}|[0-9a-f]{64})$`（按 object_format 精确校验长度）；
  内容摘要统一 SHA-256（与对象格式无关）。
- 五要素绑定中的"完整 commit SHA"语义不变（完整、非缩写）；
  **spec FR-002 无需修改**（兼容两种对象格式）。
- SHA-256 仓库的工具链兼容性（archive/LFS/子进程行为）列入 FV-0 离线
  预检对象。

## R7. 失败恢复、取消、成本与安全验收（P1-03/04/05）

### P1-03 REST 幂等、重试、异步与并发冲突语义

- **异步生成**：`POST /api/tasks/{id}/generations` 返回 **202** +
  `execution_id`；进度经 SSE（`GET /api/generations/{id}/events`）；
  轮询兜底 `GET /api/generations/{id}`。
- **SSE 续传承诺收窄（细节-3）**：V1.1 **不实现持久化事件重放**——
  SSE 事件不落库、不保证 `Last-Event-ID` 断线续传；断线后由客户端
  以 `GET /api/generations/{id}` 轮询补偿当前状态，SSE 仅承载
  连接存续期内的实时增量。API 契约按此收窄，不承诺"无损续传"。
  （若未来实现事件持久化重放，属新增能力，另行 ADR。）
- **幂等键**：生成/批准/正式保存需求等变更类接口支持 `Idempotency-Key`
  头；服务端存（键 + 请求摘要 → 响应快照）；同键同摘要重放、
  同键异摘要 409。无幂等键的重复请求仍受状态锁/唯一约束兜底。
- **重试语义**：仅携带幂等键的客户端重试安全；5xx/网络错误后重试
  返回原执行；409 表示真实冲突（附冲突对象 ID），不得盲目重试。
- **并发冲突响应表**：见 [contracts/api-endpoints.md](./contracts/api-endpoints.md)
  （活跃执行已存在/基准不可用/授权不满足/重复批准/版本冲突 →
  409/423 明细）。

### P1-03b 本地审批 API 的身份与防护（P0-B，阻断项）

- **身份区分规则**：审批类接口的合法主体仅限**经认证的用户会话**
 （登录/本地绑定令牌 + 会话级权限 role=user）。Agent/自动化组件
  **不存在**可调用审批接口的身份：其进程凭据中不含用户会话令牌，
  服务端对审批写入类端点做主体类别校验（session 主体 vs 非会话
  主体），非用户会话一律 401/403 + 安全事件（FR-033/041）。
- **服务端强制三件套**：
  ①**身份鉴别**：会话令牌（HttpOnly + Secure Cookie 或等价本地会话），
    非仅绑定 127.0.0.1 即视为已认证——回环地址不区分进程身份；
  ②**授权**：会话角色校验（role=user 才可审批）；
  ③**浏览器跨站防护**：状态变更接口要求 CSRF 令牌（双提交或
    SameSite=Strict 会话 + 自定义请求头校验），叠加 Origin/Referer
    校验作为纵深。
- **明确否定**：**不得仅依靠 CORS、Origin 校验或前端按钮禁用**作为
  身份验证——CORS 是浏览器策略，不约束非浏览器进程；本地 Agent 可
  直接发 HTTP 请求，必须被服务端身份层拒绝（S13）。
- **S13 验收**：以 Agent 进程直接向批准接口发 HTTP 调用（含伪造
  Origin/无 CSRF/无会话），断言全部被拒绝且产生安全事件；用户会话
  正常批准仍成功。

### P1-04 安全验收覆盖补强（真实外发/敏感内容/权限隔离）

新增/强化用例（quickstart S 系列扩至 S12+）：

- **S9 真实外发核对**：生成期间网络观测（防火墙日志/代理），断言仅
  授权端点流量；SendAuditRecord 与观测一致。
- **S10 权限隔离穿透**：工具写文件/执行命令/越界读取/加载目标仓库
  settings·MCP 全部失败并留审计；以 OS 级行为为准判定。
- **S11 敏感 canary**：合成仓库与工具返回中埋入密钥 canary，断言
  未出现于出站 manifest 之外的任何入模内容、日志、费用信息。
- **S12 审计防篡改目标与机制对齐（细节-2）**：目标 = 检测对
  **快照归档与核验记录的篡改**（内容寻址归档 SHA-256 复核 +
  VerificationAttempt 证据引用校验），**不承诺**检测任意数据库篡改。
  普通 append-only 应用约定无法对抗持有 DB 文件写权限的攻击者
  （可整体重写表数据）；DB 级防篡改须哈希链 + 外部锚点（如周期性
  将链头哈希写入只读介质/签名服务）——**V1.1 不实现**，仅在遗留
  风险声明此威胁模型边界。S12 断言范围按此收窄。

### P1-05 Token 用量与费用分类独立表示

- **修正**：`usage`（Token 实际用量）与 `cost`（费用三类）是**两个独立
  维度**，不得合并为单一 basis 字段：
  - `usage: {input_tokens?, output_tokens?, cache_read_tokens?, …} | null`
    + `usage_basis: actual | unavailable`（仅两类：有无实际返回）；
  - `cost: {amount?, currency?, basis: actual | estimated | unknown, method?}`
    （estimated 须注明算法；unknown 显示"不可用"）。
- 场景：Token 用量 actual 而费用 unknown（常见）；或两者皆 unknown。
  UI 分栏展示，任一维度不得由另一维度推断（SC-011 语义不变，FR-051
  无需修改）。
- 凭据永不出现于 usage/cost 结构（FR-042）。

**费用限制的可强制性（细节-4，不夸大保证）**：

| 限制 | 可强制性 | 说明 |
|---|---|---|
| 调用次数上限 | **本地可强制** | 执行前计数器检查，达到上限拒绝新调用（宿主实现） |
| Token 量上限 | **本地可强制（事后计）** | 按响应累计；超限后拒绝后续调用——单次调用的输入 Token 量在发出前只能按组装内容估算，**不能精确预控** |
| 单请求 max_tokens | **可强制（请求参数）** | 请求级上限可硬性设置 |
| 金额上限 | **不可本地强制** | 依赖提供方计费数据（费率/折扣/缓存计价），本地无实时权威数据；只能"事后核对 + 触顶中止后续"，**不得宣称预算硬控制** |
| Token/费用实际数据 | 依赖提供方返回 | 可得性由 FV-5 盘点；不可得即标注 unknown（FR-051） |

## 遗留风险（修订后）

1. Agent SDK Windows/认证/费用仍未验证——FV 通过前候选 A 不得写死。
2. OS 级隔离（受限令牌/防火墙规则）实现复杂度为推测级评估，FV-3/7 与
  实现期 ADR 验证；不足则升级强隔离（独立用户/沙箱）。
3. 敏感排除规则非绝对安全（FR-016 不变）——靠四层漏斗 + canary 测试。
4. 三状态并发正确性依赖部分唯一索引 + CAS 事务实现，须正常+失败双
  场景测试（宪章原则 II）。
5. 使用条款/计费规则版本敏感，采用前重新核实（AGENTS.md §5.6）。
6. FV-7 观测边界残留（P0-C）：加密请求体逐字节内容与提供方侧留存
  **不可可靠观测**，只能记录为「未验证」——验收报告不得声称全量通过。
7. 金额上限**不可本地强制**（细节-4）：预算硬控制不成立，仅能事后核对
  + 触顶中止；依赖提供方计费数据的语义由 FV-5 盘点后回填。
