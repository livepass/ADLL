**H4 替代方案（批准人裁定其一）**：

1. **`task_budget`**（API 侧 token 预算，beta）——最接近请求级 token
   限额；beta 面版本敏感，不满足时退回 2/3。
2. **`max_turns` + 事后 Token 计数 + 触顶中止**——零新增参数，
   控制力较弱，如实按「事后强制」表述。
   **（技术审查推荐 2026-10-18；推荐 ≠ 批准，裁决仍待签署）**——
   配套纪律（用户重申）：**不得**将会话轮数等同底层 API 请求次数，
   **不得**宣称严格 Token 上限。
3. 若必须请求级 `max_tokens` **硬限**：属降级候选 C（Messages API
   直连该参数可硬设）或 AgentAdapter 契约映射的**架构决策**，
   须重走 **ADR + 人工批准**，**不在本计划内擅自切换**。

**表述纪律**：任何「≤N tokens / ≤X 元」在报告中必须附控制能力分级；
估算值、事后计、预算感知、beta 辅助限制**一律不得**表述为绝对硬
上限。**金额与 Token 均不得作绝对保证**——本地只能做到调用次数/轮数
硬限 + Token 事后计 + 金额事后核对 + 触顶中止。
